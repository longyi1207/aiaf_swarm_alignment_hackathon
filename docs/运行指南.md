# 运行指南（DGX Spark / 任意 CUDA 机器）

## 0. 连上机器

朋友的 Spark 用 Tailscale 共享，参考 NVIDIA 的官方 playbook：https://build.nvidia.com/spark/tailscale.md

1. 朋友在 Spark 上给你**单独开一个账号**。你把自己的 SSH **公钥**发给他，加进 `~/.ssh/authorized_keys`。**私钥不要给任何人。**
2. 你在 Mac 上装 Tailscale，接受朋友分享的机器，然后 `ssh 你的用户名@<spark 的 tailscale 名字>`。
3. 长任务一律放在 `tmux` 里跑，断线后进程不会停：

```bash
tmux new -s swarm
tmux attach -t swarm
```

## 1. 环境

Spark 是 ARM（aarch64）+ CUDA。**先确认 PyTorch 能看到 GPU**。GB10 的支持我没有核实过，这是上机后第一件要查的事。

```bash
git clone git@github.com:longyi1207/aiaf_swarm_alignment_hackathon.git && cd aiaf_swarm_alignment_hackathon
curl -LsSf https://astral.sh/uv/install.sh | sh      # 如果还没有 uv
uv sync --extra model --group dev
uv run python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

如果 `cuda.is_available()` 是 False，说明 uv 装到的 torch 没有带 CUDA。改用 NVIDIA 官方的 PyTorch 容器（NGC），在容器里 `pip install -e .`。

确认 GPU 可用之后：

```bash
uv run pytest -q                                   # 50 项，其中 6 项需要 torch
huggingface-cli download Qwen/Qwen3.5-9B           # 约 19 GB
```

**网络隔离（建议）**：agent 的 `run_python` 工具只做了进程级隔离：独立进程、干净的环境变量、超时、资源上限，**但没有断网**。正式实验最好在没有网络的容器里跑：

```bash
docker run --gpus all --network none -v ~/.cache/huggingface:/hf -e HF_HOME=/hf -e HF_HUB_OFFLINE=1 \
  -v $PWD:/work -w /work <pytorch镜像> bash -lc "pip install -e . && swarmtom run configs/run_phase0_baseline.yaml"
```

## 2. 第一次上机：先跑 1 局冒烟测试

在 `configs/run_phase0_baseline.yaml` 的基础上做一个最小配置，只跑 1 局：

```bash
sed -e 's/run_id: phase0_baseline/run_id: qwen_smoke/' \
    -e 's/seeds: \[101, 102, 103, 104\]/seeds: [101]/' \
    -e 's/k_evidence: \[2, 3, 4\]/k_evidence: [3]/' \
    -e 's/harm: \[low, high\]/harm: [high]/' \
    -e 's/communication: \[isolated, discuss\]/communication: [discuss]/' \
    configs/run_phase0_baseline.yaml > configs/run_qwen_smoke.yaml
HF_HUB_OFFLINE=1 uv run swarmtom run configs/run_qwen_smoke.yaml
```

跑完检查三件事：
1. `runs/qwen_smoke/progress.log`：每一步的批大小、生成耗时、tok/s。由此估算完整实验要跑多久。
2. **工具调用解析是否正常**。Qwen3.5 的工具调用格式我没能在本地验证；解析器同时支持 Qwen2.5/3 的 JSON 格式和 Qwen3-Coder 的 XML 格式。下面的命令统计"模型输出里有 `<tool_call>` 却没解析出调用"的次数：

   ```bash
   python - <<'EOF'
   import json, glob
   for f in glob.glob("runs/qwen_smoke/games/*/events.jsonl"):
       ev = [json.loads(l) for l in open(f)]
       m = [e for e in ev if e["type"] == "model"]
       bad = [e for e in m if "<tool_call>" in e["raw"] and not e["tool_calls"]]
       print(f, "model turns", len(m), "parse errors", sum(bool(e["parse_errors"]) for e in m), "unparsed", len(bad))
   EOF
   ```

   如果 `unparsed` 不为 0，把一条 `raw` 发给我，我来改 `src/swarmtom/llm/parse.py`。
3. 读一局的完整对话：`runs/qwen_smoke/games/<id>/state.json` 里的 `agents.<名字>.messages`，看 agent 是不是真的在用 pandas 联表、算规则、在权衡。

## 3. Phase 0 基线校准

```bash
uv run swarmtom run configs/run_phase0_baseline.yaml      # 中断后再运行同一条命令会从断点续跑
uv run swarmtom score runs/phase0_baseline                # 写 results/agents.csv、games.csv
```

- **批大小** `backend.batch_size`：Spark 有 128 GB，可以先试 16–32；显存不够（OOM）时会自动对半拆分。
- **调试**：可以加 `--max-ticks N`，跑 N 步就停，之后用同一条命令续跑。

通过标准见设计 §8：
- 分析正确率（`classification_accuracy`、`found_own_f`）≥ 70%；
- 举报率在 15%–85%；
- 推理里确实有权衡。

不满足就改场景，回到第 2 步。

## 4. 更快的基线（可选）：vLLM

只跑**不损伤**的基线时，可以在 Spark 上起一个 vLLM 服务（带前缀缓存，比 transformers 快很多），然后把配置里的 backend 换成：

```yaml
backend:
  type: openai_compat
  base_url: http://localhost:8000/v1
  model: Qwen/Qwen3.5-9B
  max_tokens: 2048
  temperature: 0.6
  concurrency: 32
  extra_body: {chat_template_kwargs: {enable_thinking: true}}
```

**有损伤的条件必须用 `type: hf`**，vLLM 做不了按 agent 的激活干预。注意：同一组比较里的所有条件要用同一个后端，否则后端差异会混进结果。

## 5. 主实验

Phase 0b 剂量配平通过后再跑：

```bash
uv run swarmtom run configs/run_main.yaml
```

N（agent 数）、门槛、轮数、步数上限都在配置文件里，按硬件调整即可。
