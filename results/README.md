## 解读时必须知道的一个问题（2026-11-07 23:35 发现并修复）

vLLM 的前缀缓存只按 token 匹配、不区分损伤条件。修复（`cache_salt`）之前，同一进程里有多个损伤条件、输入开头相同时，后处理的条件会复用别的条件算好的 KV，开头部分没有被正确损伤：

- **受影响**：用 vLLM 跑的剂量检查（`dose_check_v4`、`v4b`、ToM v2 的三次粗筛 / 重测）和 agent 能力检查——损伤主要只作用在生成的回答和思考上，效应可能被低估，"无效果"可能是假阴性，个别任务的 none 基线也可能复用了带损伤的 KV。
- **基本不受影响**：主实验的举报决定——每组后来都在独立的新进程里从存档重跑，整个对话在正确条件下重新编码；受影响的只是主实验前 6 轮（7 组同跑）、tom + tom_all30 同跑的 4 轮、修复前最后一批的 4 轮里 agent 写下的分析文字。
- **不受影响**：校准（单一条件）、v3（HF 后端，逐行掩码、无前缀缓存）、修复后的双重分离检查。
